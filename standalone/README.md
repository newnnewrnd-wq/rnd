# NEW&NEW Formula Lab — 직원 계정 버전

ChatGPT 계정 없이 전용 아이디와 비밀번호로 사용하는 배합 시뮬레이터입니다. 기존 배합 계산 프로그램에 실제 서버 인증과 계정 관리 기능을 붙였습니다.

## 포함된 기능

- 최초 관리자 계정 생성: 서버의 일회용 초기 설정 키가 필요합니다.
- 관리자: 직원 계정 발급, 계정 목록 조회, 사용 중지/재허용, 임시 비밀번호 초기화.
- 직원: 전용 아이디 또는 이메일 형식의 아이디로 로그인, 비밀번호 변경, 로그아웃.
- 임시 비밀번호는 발급 화면에서 한 번 표시되며 24시간 이내 사용해야 합니다. 첫 로그인 후 변경을 마쳐야 시뮬레이터에 접근할 수 있습니다.
- 계정 중지, 비밀번호 변경, 초기화 시 기존 세션을 폐기합니다.
- 43종 원료, 예시 처방, g/kg 투입량, 유효분 %, ppm, 원료비, 입력 규격 검토 및 CSV 다운로드 기능을 그대로 사용합니다.

메일 주소는 로그인 아이디로만 사용합니다. 이메일 발송, 이메일 소유 확인, 회사 SSO, 공개 회원가입 기능은 없습니다. 실제 직원에게 아이디를 발급하는 권한은 관리자에게 있습니다. 발급한 임시 비밀번호는 관리자가 직접 전달합니다.

## 현재 제공 상태

독립 서버용 소스와 실행 패키지입니다. 기존 `chatgpt.site` 주소에는 이 서버를 배포하지 않았습니다. 기존 주소의 ChatGPT 접근 정책은 변경하지 않았습니다. 외부에서 직원 계정만으로 접속하려면 이 패키지를 회사 서버 또는 별도 웹 호스팅에 실행해야 합니다.

현재 버전의 계정 데이터는 SQLite에 저장되어 서버 재시작 후 유지됩니다. 처방은 아직 CSV 보관 방식이며, 계정별 처방 저장·기기 간 처방 동기화 기능은 포함하지 않았습니다.

## Windows에서 먼저 실행

1. [Node.js 24 LTS](https://nodejs.org/en/download)를 설치합니다.
2. 압축을 푼 폴더에서 `start-windows.bat`를 실행합니다. 별도 패키지 설치는 없습니다.
3. 표시된 로컬 주소 `http://127.0.0.1:3000`을 브라우저에서 엽니다.
4. 최초 실행 때 실행 창에 표시된 초기 설정 키를 입력하고 관리자 아이디·이름·비밀번호를 정합니다.
5. ‘직원 계정 관리’에서 계정을 발급합니다. 직원은 발급된 임시 비밀번호로 로그인한 뒤 새 비밀번호를 설정합니다.
6. 프로그램을 사용하는 동안 실행 창을 열어두고, 종료할 때 Ctrl+C를 누릅니다.

macOS/Linux는 같은 폴더에서 `sh start-macos-linux.sh`로 실행합니다. 로컬 실행은 해당 컴퓨터에서만 접속할 수 있습니다. 다른 컴퓨터에서도 쓰려면 아래 서버 배포가 필요합니다.

## 회사 서버에 배포 — Docker + HTTPS

도메인과 Docker Compose를 사용할 수 있는 Linux 서버를 기준으로 합니다.

1. 패키지 전체를 서버에 놓고 `.env.example`을 `.env`로 복사합니다.
2. `DOMAIN`을 실제 도메인으로 바꾸고 해당 도메인의 DNS를 서버로 연결합니다.
3. 아래 명령으로 생성한 무작위 값을 `.env`의 `SETUP_TOKEN`에 지정합니다. 이 키는 관리자 초기 설정 때 사용하므로 외부에 공개하지 않습니다.

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
```

4. 서버의 HTTP/HTTPS 접근이 준비되면 실행합니다.

```sh
docker compose up -d --build
```

5. `https://실제도메인/setup`에서 초기 설정 키로 관리자를 등록합니다. 이후 `/login`은 직원 계정 로그인, `/admin`은 관리자 기능입니다.

`account-data`는 계정과 세션 데이터, `caddy-data`와 `caddy-config`는 HTTPS 운영용 저장소입니다. 데이터 볼륨을 삭제하면 계정이 사라지므로 재배포 때 볼륨을 유지하세요. 초기 설정 키는 관리자 생성 후 데이터베이스에서 폐기되므로 재사용할 수 없습니다.

## Railway 등 Node/Docker 호스팅

배포 연결이 준비되면 같은 Dockerfile을 사용할 수 있습니다. 다음 항목을 지정해야 합니다.

| 설정 | 값 |
|---|---|
| PUBLIC_ORIGIN | 실제 `https://` 접속 주소. 경로나 끝 슬래시 없이 지정 |
| NODE_ENV | production |
| DATABASE_PATH | 지속 볼륨 안의 SQLite 경로, 예: `/app/data/accounts.sqlite` |
| SETUP_TOKEN | 32자 이상의 임의 생성 키. 최초 관리자 생성용 |
| PORT | 호스팅 서비스가 주입한 포트. 기본 3000 |
| TRUST_PROXY_HOPS | 신뢰하는 앞단 프록시 개수. 직접 연결은 0, 제공 Compose는 1 |

지속 볼륨의 소유권을 앱 실행 사용자(Node 이미지의 `node`, 기본 UID 1000)가 쓸 수 있게 설정하세요. **한 개 앱 인스턴스**를 사용합니다. SQLite 파일을 여러 서버에서 공유하는 구성은 지원하지 않습니다. 호스팅의 `/healthz`를 상태 확인 경로로 사용할 수 있습니다.

## 운영과 복구

- 비밀번호는 무작위 salt를 사용하는 scrypt(N=32768, r=8, p=3) 해시로만 저장합니다.
- 세션은 무작위 256비트 토큰이며 서버에는 토큰의 SHA-256 해시를 저장합니다. 일반 세션 유효 기간은 8시간, 임시 비밀번호 세션은 20분입니다.
- 실제 배포에서는 HTTPS 및 `Secure`, `HttpOnly`, `SameSite=Strict` 쿠키를 사용합니다. 변경 요청은 Origin과 CSRF 토큰을 검사합니다.
- 서버에서 배합 화면·계산 스크립트·관리자 API의 접근 권한을 확인합니다. 화면만 가리는 방식이 아닙니다.
- 로그인 횟수를 데이터베이스에서 제한하고, 비밀번호 해시 계산 동시 실행을 제한합니다.
- 서비스의 데이터베이스와 백업은 개인정보를 포함하므로 서버 접근 권한으로 관리합니다. 앱 자체는 SQLite 파일 암호화를 제공하지 않습니다.
- 비밀번호 정책은 15~128자이며 일부 흔한 값과 아이디 포함을 막습니다. 전체 유출 비밀번호 데이터베이스 대조나 MFA는 포함하지 않았습니다.
- 계정 백업은 서버를 중지한 뒤 `accounts.sqlite`와 같은 디렉터리의 `accounts.sqlite-wal`, `accounts.sqlite-shm`이 있으면 함께 보관하거나 SQLite의 정식 백업 절차를 사용하세요.

관리자 비밀번호를 잊은 경우 서버를 중지하고, 신뢰할 수 있는 서버 터미널에서 기존 DB 경로를 지정하여 실행합니다. 생성된 임시 비밀번호는 실행 창에서만 표시되며 최초 로그인 때 변경해야 합니다.

```sh
DATABASE_PATH=/실제경로/accounts.sqlite node standalone/recover-admin.mjs
```

## 검증

```sh
node --test standalone/test/accounts.test.mjs
```

HTTP 요청으로 비로그인 접근 차단, 최초 관리자 설정, 직원 발급, 임시 비밀번호 강제 변경, 관리자 권한 분리, CSRF, 비밀번호 초기화, 세션 폐기, 시도 횟수 제한과 서버 재시작 후 계정 보존을 검증합니다. 브라우저에서의 시각적 검증과 실제 외부 호스팅 검증은 아직 수행하지 않았습니다.
